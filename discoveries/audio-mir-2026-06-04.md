# Audio / MIR / Music Theory discoveries — 2026-06-04

Scoring is 1–5 against relevance to **ASA** and **Harmonia**. Anything below
3 was dropped. Source for this run was a hand-supplied batch of 14 starred
audio/MIDI repos (screenshots), not a keyword sweep; each was ground-truthed
against its actual GitHub page. Dedup'd against `discoveries/_seen.txt`
(124 entries at time of run — none of the 14 were already listed).

Run against the corrected routine spec (`routines/audio-mir.md`): **ASA is a
server-side Python/FastAPI app** doing analysis on NATIVE libraries (Essentia
primary, plus librosa, torchcrepe, Demucs; PyTorch already in the stack) and a
Gemini/LLM layer; it already emits a large analysis JSON (spectral, chroma/
HPCP, key, chords, genre, EBU R128, BPM/beats, structure, stems, melody).
Native Python/C++/Rust and PyTorch models are first-class — **no credit for
browser/WASM/client-side**. **Harmonia** is a React chord-progression /
reharmonization tool on Tonal.js (symbolic-first).

None of the batch touch symbolic chord theory, so nothing scored as
Harmonia-relevant or Both. The audio→MIDI / stem-extraction cluster is the
real overlap with ASA's pipeline.

## ASA-relevant

### [jdez23/MiDiMe](https://github.com/jdez23/MiDiMe) — **4**
Full-stack drum-pattern extractor: a Django backend runs **Demucs v4** stem
separation (with a frequency-band fallback) + onset detection + grid
quantization, and a React frontend shows waveforms and an editable step
sequencer before MIDI export — explicitly "no client-side audio processing"
(updated April 2026). This is almost a scale model of ASA's own architecture
(server-side Python analysis on Demucs + a React UI), so it's the most useful
reference in the batch for the analysis-job → React-visualisation contract,
even if the MIR itself is narrower than ASA's.

### [Omodaka9375/MIDIfren](https://github.com/Omodaka9375/MIDIfren) — **4**
Pure-Python audio→MIDI processor (CLI **and** web UI) that does stem
separation (vocals/melody/drums/bass), BPM detection, grid quantization,
pitch-bend detection, and silence trim/normalise across wav/mp3/flac. Sits
squarely on ASA's server-side stack and covers several stages ASA already
runs (stems, BPM, melody→MIDI), so it's a concrete reference for the
audio→symbolic conversion ASA's JSON stops short of emitting.

### [justinsalamon/audio_to_midi_melodia](https://github.com/justinsalamon/audio_to_midi_melodia) — **3**
Justin Salamon's melody-extraction→MIDI tool built on the classic **Melodia**
pitch-contour algorithm plus a note-segmentation pass (also exports JAMS).
A foundational MIR reference for the melody→note-segmentation step, but it's
Python 2.7, last touched 2019, and leans on the proprietary Melodia Vamp
plugin — so it's algorithm/lineage reading, not liftable code (ASA already
does melody via torchcrepe).

### [jonas-nothnagel/drum-beat-extractor](https://github.com/jonas-nothnagel/drum-beat-extractor) — **3**
Single-script Python tool that extracts MIDI drum patterns from audio files.
On-stack and on-topic for ASA's rhythm/onset side, but it's thin (3 stars, one
script, minimal docs) — worth a skim as a compact onset→MIDI recipe rather
than a dependency, and clearly outclassed by MiDiMe/MIDIfren above.

## Tangential but interesting

### [meyda/meyda](https://github.com/meyda/meyda) — **3**
Well-established JS/TypeScript audio-feature-extraction library (1.6k stars;
spectral centroid, ZCR, MFCC, etc.) that runs both offline and live via the
Web Audio API. ASA won't *use* it (it's the JS analogue of ASA's native
Essentia/librosa stack, and the routine gives no credit for browser/client-
side audio), but its feature catalogue and definitions are a clean cross-check
reference for the spectral features ASA emits — kept as a reference, not a
candidate dependency.

Dropped (off-domain, thin, or wrong layer; all 14 surfaced this run were added
to `_seen.txt` so they don't resurface):

- **svsdval/video2midi** (356★, Python) — Synthesia-video→MIDI by
  frame-by-frame computer vision on a keyboard overlay. MIDI *output*, but the
  input is video CV, not audio DSP/MIR — off-pipeline for ASA. Score 2.
- **danryland/groove-ai** (Vue) — GPT-3.5 *generates* drum grooves + MIDI
  export. ASA's LLM layer *interprets measured analysis* into Ableton
  recommendations; this is prompt→generation, the opposite direction, and on a
  cloud Vue/Supabase stack. Score 2.
- **AxelCurso/youtube2midi** (Python, 1★) — thin, undocumented YouTube-audio→
  MIDI wrapper; nothing to learn next to MIDIfren. Score 2.
- **supercollider/supercollider** (C++, 6.6k★) — venerable audio server /
  language / IDE for **synthesis and algorithmic composition**. ASA does
  analysis, not synthesis; famous but off-target. Score 2.
- **gvellut/dmp_midi** (Python, 54★) & **stephenhandley/DrumMachinePatterns**
  (JS) — static converters/datasets of the "200/260 Drum Machine Patterns"
  books into MIDI/JS. Symbolic drum data, no analysis or chord theory. Score 2.
- **echolevel/Acid-Injector** (JS) — in-browser converter of STING M4L MIDI
  clips → Behringer Synthtribe `.seq` / `.syx` sysex for a TD-3. Niche
  hardware-format plumbing; neither analysis nor chords. Score 1.
- **RyoK3N/Akai_MPC_25** (Python, 1★) — live MIDI-controller + MP3/YouTube
  playback rig. Performance tooling, no MIR. Score 1.
- **spite/WebAudioExtension** (JS, dormant since 2015) — Chrome DevTools panel
  for visualising Web Audio API routing graphs. A browser-dev debug tool, not
  MIR/analysis. Score 1.

Not evaluated (out of stream): **pbakaus/impeccable** (a design-language for AI
