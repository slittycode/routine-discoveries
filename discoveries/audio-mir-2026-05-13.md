# Audio / MIR / Music Theory discoveries — 2026-05-13

> **Correction (2026-05-23): Harmonia was mis-described here.** Harmonia is **real** but is slittycode's **unpublished, single-file, dependency-free vanilla-JS** chord-progression / reharmonization tool — **not** a React+Tonal.js project, and **not** a GitHub repo (`github.com/slittycode/harmonia` → 404). It is **not** a "phantom" (it exists; the ASA-docs "phantom" wording overshot). Any `(H)` / "Harmonia-relevant" / stack-fit notes below therefore stand only as **conceptual** (UX / idea / dataset) references, never dependency or stack-compatibility judgments. History preserved, not re-scored.

Scoring is 1–5 against relevance to **ASA** (Essentia.js DSP pipeline:
mel-spectrograms, tonal balance, dynamics, loudness) and **Harmonia**
(React chord-progression/reharmonization on Tonal.js). Anything below 3
was dropped.

## ASA-relevant

### [creightonlinza/forever-jukebox](https://github.com/creightonlinza/forever-jukebox) — **5**
End-to-end Infinite-Jukebox replacement: madmom-beats-lite + Essentia
generate beats/segments/sections locally and serve them through a
small REST API, replacing Spotify's now-dead Audio Analysis endpoint.
24★, TypeScript+Python, created Jan 2026. Direct reference for the
shape of ASA's analysis → JSON contract.

### [httpsworldview/openmeters](https://github.com/httpsworldview/openmeters) — **4**
Linux audio metering in Rust: short-term/momentary LUFS to ITU-R
BS.1770-5, true peak, A-weighted spectrum, spectrogram with **spectral
reassignment** for sharp time-frequency resolution, oscilloscope,
goniometer. 135★, created Oct 2025. The reassignment trick and the
exact BS.1770 revision are worth lifting; UI is wgpu/Iced.

### [Ircam-Partiels/Partiels](https://github.com/Ircam-Partiels/Partiels) — **4**
IRCAM's Vamp-plugin host wrapping FFT, LPC, transients, F0, formants,
and tempo behind a JUCE GUI, with batch CLI and exports to CSV/SDIF/
JSON/REAPER/Max/PD. 74★, C++. Useful as a reference for how a serious
analysis tool structures multi-track, multi-channel pipelines and
result interchange — and the SDIF export format is worth a look for
ASA result storage.

### [bananaofhappiness/soundscope](https://github.com/bananaofhappiness/soundscope) — **3**
Rust TUI loudness analyzer: LUFS + true peak + FFT spectrum + min-max-
decimated waveform on files or live mic. 174★. Smaller scope than
openmeters and CLI-only; mostly useful as a second BS.1770
implementation to cross-check against.

### [JeffreyCA/spleeter-web](https://github.com/JeffreyCA/spleeter-web) — **3**
Self-hostable React+Django app for vocal/bass/drums isolation backed
by Spleeter, Demucs, and BS-RoFormer. 544★, pushed within the window
but the project itself is from 2019. Not a new idea, but the React
front for queueing/running stem jobs is a useful pattern if ASA grows
a stem-separation stage. Drop if you already know Spleeter/Demucs from
upstream.

## Harmonia-relevant

### [ptnghia-j/ChordMiniApp](https://github.com/ptnghia-j/ChordMiniApp) — **5**
Next.js + Flask app that does chord recognition (Chord-CNN-LSTM, BTC-
SL/PL from ISMIR2019), beat tracking (Beat-Transformer + madmom),
lyrics (Music.ai + LRClib), and renders sheet via OpenSheetMusicDisplay
with chord-db guitar diagrams. 282★, TypeScript. This is the closest
public neighbor to Harmonia's product surface; read its UX choices
before adding new ones.

### [spyroskantarelis/chordonomicon](https://github.com/spyroskantarelis/chordonomicon) — **4**
666K symbolic chord progressions with section labels (verse/chorus/
bridge), genre, and release date, encoded as single chord / triad
(root+quality+bass) / tetrad (+extensions) tokens on Hugging Face.
143★. Drop-in training/eval set for any reharmonization model and a
benchmark with RNN/GRU/LSTM baselines already published.

### [vpavlenko/rawl](https://github.com/vpavlenko/rawl) — **4**
React+TS MIDI/MusicXML visualizer that color-codes pitch classes ("12
colors") and annotates harmonic language across classical, jazz,
chiptune, modal systems. 81★. Worth studying for piano-roll rendering
and pedagogically motivated harmony annotations; the "harmony as
flags" framing is a Harmonia-adjacent take.

## Both

### [rzru/nightingale](https://github.com/rzru/nightingale) — **4**
Tauri (Rust + React) karaoke app combining Demucs/UVR vocal isolation,
WhisperX/Parakeet-v3 lyric transcription with word timestamps, real-
time pitch scoring, and key/tempo shifting. 1.1k★, created Mar 2026.
Hits both projects: the local-PyTorch-from-Tauri shape is a template
for ASA, and the pitch-scoring/key-shift logic is adjacent to
Harmonia's note-domain code.

## Tangential but interesting

### [openvpi/GAME](https://github.com/openvpi/GAME) — **3**
Singing-voice → MIDI transcription via D3PM (structured denoising
diffusion) with adaptive boundary extraction; ONNX-exportable, Python
3.12, PyTorch Lightning. 161★. Not on-stack, but if Harmonia ever
ingests sung input the F0 + boundary outputs would be the upstream.

### [adamjmurray/producer-pal](https://github.com/adamjmurray/producer-pal)  — **3**
Max-for-Live device + MCP server letting Claude/Gemini/ChatGPT/Ollama
drive an Ableton Live session through natural language. 143★. Not
directly ASA/Harmonia, but it's the cleanest current example of M4L ↔
MCP plumbing if either project ever wants a DAW-side companion.

### [prabal-rje/latentscore](https://github.com/prabal-rje/latentscore) — **3**
Retrieval-based ambient music generation: sentence-transformer (or
LAION-CLAP) embeds a prompt, cosine-matches against ~10k pre-computed
synth configs, and drives a real-time CPU synth — no GPU, ~2s latency.
36★, Python. Interesting as a "music as configuration retrieval"
pattern; not a generative model in the usual sense.

### [JorenSix/Olaf](https://github.com/JorenSix/Olaf) — **3**
Portable acoustic fingerprinting in C with WASM and ESP32 targets.
396★, created 2020 but still actively pushed. Tangential to ASA's
core but a clean reference if you ever need audio identification or
cross-take alignment in-browser.

## Second pass — 2026-05-13 (PM)

Wider sweep across the same queries. Same scoring rubric, same drop
threshold. Dedup'd against the morning's seen list.

### ASA-relevant

#### [sanderwood/clamp3](https://github.com/sanderwood/clamp3) — **4**
ACL 2025 framework that contrastively aligns text, sheet music, audio
(via MERT features), MIDI, and images into one embedding space — think
CLAP but multi-modal and 27-language. 239★, Python, created Feb 2025.
For ASA, the value is the audio-side feature extractor and the
retrieval primitives (find tracks-like-this, prompt-to-track) — drop in
ahead of any reach for tagging/similarity.

#### [linuxmatters/jivetalking](https://github.com/linuxmatters/jivetalking) — **4**
Go CLI that measures a recording's integrated LUFS, true peak, LRA
(EBU R128), noise floor and spectral signature, then picks per-pass
filter params from that — adaptive de-essing, gating, comp, two-stage
R128 normalisation to -16 LUFS. 71★, created Nov 2025. The "measure
first, then choose parameters" pipeline is exactly what ASA's loudness
+ dynamics stage should output as recommendations.

#### [crlandsc/moises-light](https://github.com/crlandsc/moises-light) — **3**
Unofficial PyTorch implementation of "Moises-Light: Resource-efficient
Band-split U-Net" (WASPAA 2025) with RoPE bottleneck borrowed from
BS-RoFormer. 27★, created Mar 2026, training-only — no weights. Useful
as a clean modern band-split reference if ASA ever adds a separation
pre-stage; otherwise read the paper.

#### [sweetspotsoundsystem/stemgen-rt](https://github.com/sweetspotsoundsystem/stemgen-rt) — **3**
Real-time HS-TasNet 4-stem separation as a JUCE/VST3/AU plugin at
11.6 ms latency, with async inference threading and crossover/gating
DSP polish. 27★, created Jan 2026. Inference model is binary-only, so
this is reference for the *plumbing* (async ONNX in a plugin callback,
44.1k constraint) rather than a model to lift.

#### [matteospanio/torchfx](https://github.com/matteospanio/torchfx) — **3**
PyTorch-native audio DSP — filters as `nn.Module`s, composable with
`|`/`+`, differentiable, GPU. 131★, created Mar 2025. Only a couple of
filters shipped (LoButterworth, ParametricEQ); the appeal is the
pattern for batching ASA's analysis filters on GPU if it ever moves
off Essentia for a bulk pass. No MIR/loudness in-box.

### Harmonia-relevant

#### [madderscientist/noteDigger](https://github.com/madderscientist/noteDigger) — **4**
"No framework, no library" pure-JS audio-to-MIDI transcription:
optimised real-FFT STFT, CQT, ONNX nnls.js + spectral-clustering for
note picking, plus harmonic reduction and beat tracking. 268★, pushed
last week. The closest reference for the analysis half of a
browser-native Harmonia ingest path — and the deliberate zero-deps
constraint is instructive for bundle size.

#### [chromatone/chromatone.center](https://github.com/chromatone/chromatone.center) — **3**
Vue/Vite app on top of Tonal.js + abcjs + Tone.js + audiomotion-
analyzer presenting chords, scales, rhythms, and pitch-color
visualisations as PWA "instruments". 146★, started 2021 but actively
pushed. Direct overlap with Harmonia's stack; worth pillaging for
chord/scale visual idioms and the color-coded pitch palette.

### Tangential but interesting

#### [williamzujkowski/live-coding-music-mcp](https://github.com/williamzujkowski/live-coding-music-mcp) — **3**
MCP server exposing Strudel.cc to Claude/Anthropic clients for live-
coded pattern generation. 200★, TS, created Aug 2025. Same MCP-in-the-
DAW family as producer-pal but on the browser-pattern side; included
mainly as a second data point if Harmonia ever wants an LLM-driven
"reharm-as-pattern" channel.
