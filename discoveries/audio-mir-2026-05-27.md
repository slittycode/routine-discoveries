## ASA-relevant

### [Yikai-Liao/symusic](https://github.com/Yikai-Liao/symusic) — **4**
C++20 symbolic-music toolkit (MIDI / ABC) with nanobind Python bindings,
SoundFont rendering, beat / piano-roll computation, vectorised pitch /
velocity / time transforms, and ISMIR-2024 recognition; benchmarks claim
"hundreds of times faster" than pure-Python alternatives. ASA already
emits MIDI (melody + chord stages) and runs server-side on native libs,
so symusic is a natural drop-in either as a faster `pretty_midi`
replacement for note-level work or as the symbolic side of a melody /
chord round-trip — Python wheels are shipped for 3.9–3.14 on Linux /
macOS / Windows.

### [magenta/mt3](https://github.com/magenta/mt3) — **3**
Google Magenta's multi-task multi-track transcription transformer
(WAV → tokenised note events across multiple instruments simultaneously).
It's research code rather than a packaged service, but it's the canonical
modern AMT reference and a useful upgrade path for ASA's melody /
torchcrepe-based note-extraction stage — particularly for polyphonic
inputs where pitch tracking alone undersells what's on the stems.

### [SUC-DriverOld/MSST-WebUI](https://github.com/SUC-DriverOld/MSST-WebUI) — **3**
Python WebUI that bundles the Music-Source-Separation-Training framework
together with Ultimate Vocal Remover, supporting MSST / VR architectures
(incl. `swin_upernet`), ensemble inference, and a custom preset pipeline.
Tangential to ASA's L2 (which currently runs Demucs and is happy), but
useful as a reference for "swap separation backend" — directly comparable
to `undef13/splifft` already in the shortlist, and worth knowing about if
ASA ever needs to train / evaluate alternative stem models.

### [gluon/AbletonLive12_MIDIRemoteScripts](https://github.com/gluon/AbletonLive12_MIDIRemoteScripts) — **3**
Decompiled / reconstructed Python MIDI Remote Scripts source for **Live
12** specifically (147★, sibling to the same author's already-popular
Live 11 repo). ASA's Phase 2 produces Live 12 device / parameter
recommendations; this is the canonical reference for *what's actually
addressable* from Live 12's control-surface API — useful next to the
existing `bschoepke/ableton-live-mcp` and `adamjmurray/producer-pal`
entries when Phase 2 needs to ground a recommendation in an
actually-callable surface.

### [LiZhuoming-lab/seemusic](https://github.com/LiZhuoming-lab/seemusic) — **3**
Local-only Streamlit workspace that runs spectral analysis (RMS,
spectral centroid, novelty curves) side-by-side with music21-driven
symbolic analysis (MusicXML / MIDI / Kern → harmony, cadence, thematic
recurrence) for musicology research. The interesting bit for ASA isn't
the code (it's a thin Streamlit app) but the UX pattern — "DSP measurement
on the left, theory-level reading on the right, both pointing at the same
timeline" is the same shape ASA's Phase-1-JSON + Phase-2-Gemini output
wants to surface to the user. Counted as `(H)`-relevant only in the
legacy sense — Harmonia is a phantom.
