# Audio / MIR / Music Theory discoveries — 2026-06-23

Scoring is 1–5 against relevance to **ASA** and **Harmonia**. Anything
below 3 was dropped. Dedup'd against the consolidated `discoveries/_seen.txt`
(124 entries at time of run).

Run against the corrected routine spec (`routines/audio-mir.md`): **ASA is
a server-side Python/FastAPI app** doing analysis on NATIVE libraries
(Essentia primary, plus librosa, torchcrepe, Demucs; PyTorch already in
the stack) and a Gemini/LLM layer; it already emits a large analysis JSON
(spectral, chroma/HPCP, key, chords, genre, EBU R128, BPM/beats,
structure, stems, melody). Native C/C++/Rust/Python and PyTorch models are
first-class. **Harmonia** is a React chord-progression / reharmonization
tool on Tonal.js.

## ASA-relevant

### [mir-aidj/all-in-one](https://github.com/mir-aidj/all-in-one) — **4**
End-to-end music structure analyzer (788★, Python/PyTorch, actively
maintained 2026) that runs a single model to produce timestamped beats,
downbeats, chord labels, key estimation, and section boundaries in one
forward pass. That maps directly onto five of ASA's existing output fields
at once; useful both as a cross-validation reference against ASA's
per-feature Essentia pipeline and as a source of section-boundary ground
truth, which ASA currently leaves to a separate segmentation step.

### [Music-and-Culture-Technology-Lab/omnizart](https://github.com/Music-and-Culture-Technology-Lab/omnizart) — **4**
Python/TF2 toolkit (1915★) that transcribes audio into structured MIDI
outputs across five tracks: vocal melody, drums, chord labels, beat
positions, and pitched instruments (piano, guitar). Its chord + beat
modules parallel ASA's pipeline and can cross-validate; the pitched-
instrument transcription is the gap ASA doesn't currently fill. Actively
maintained through 2026 and installable as a Python package, so adding a
transcription step to ASA's analysis JSON is a realistic near-term action.

### [CPJKU/madmom](https://github.com/CPJKU/madmom) — **4**
CPJKU's broad MIR signal-processing library (1663★, Python/Cython), the
upstream codebase from which beat_this and partitura were later factored
out — both already in ASA's stack. Implements its own DL models for beat,
downbeat, chord, key, onset, and tempo, Cython-optimized for throughput.
Since ASA already depends on two CPJKU repos, madmom is the natural next
layer for any feature where a second algorithm opinion would improve
robustness.

### [mjhydri/BeatNet](https://github.com/mjhydri/BeatNet) — **3**
Real-time joint beat, downbeat, tempo, *and meter* tracker (496★,
Python/PyTorch, ISMIR 2021) using CRNN + particle filtering. The key
addition over beat_this is meter detection (2/4, 3/4, 4/4) — which ASA
doesn't currently emit but which directly informs Ableton's grid-snapping
and clip warp recommendations. Could slot in as a post-beat step or
parallel run alongside beat_this.

### [openvpi/SOME](https://github.com/openvpi/SOME) — **3**
Singing-Oriented MIDI Extractor (695★, Python/PyTorch): converts an
isolated vocal track to quantized note-on/note-off MIDI with velocity
estimates. In ASA's pipeline, Demucs produces the vocal stem and
torchcrepe produces continuous F0; SOME bridges the gap to note-level MIDI
segments, filling the melody transcription output that ASA doesn't
currently produce.

### [aubio/aubio](https://github.com/aubio/aubio) — **3**
C/Python library (3712★) for onset detection, pitch tracking, beat
induction, and tempo estimation — the standard alternative algorithm
family alongside Essentia. Uses YIN pitch and its own HFC/HWD onset
detectors, which have different bias/variance profiles from Essentia's
equivalents. Not in _seen.txt despite being a foundational tool; worth
logging as a validation baseline for any ASA feature where the Essentia
result looks suspect.
