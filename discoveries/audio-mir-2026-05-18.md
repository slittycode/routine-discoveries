# Audio / MIR / Music Theory discoveries — 2026-05-18

Scoring is 1–5 against relevance to **ASA** (Essentia.js DSP pipeline:
mel-spectrograms, tonal balance, dynamics, loudness) and **Harmonia**
(React chord-progression/reharmonization on Tonal.js). Anything below 3
was dropped.

## ASA-relevant

### [wavey-ai/mel-spec](https://github.com/wavey-ai/mel-spec) — **4**
Rust mel-spectrogram + streaming STFT + model-free VAD, Whisper-compatible
filterbanks, ~480× realtime on M1 Pro CPU, with WASM and experimental
CUDA/wgpu backends. 89★, pushed last week. The streaming STFT and the
WASM build are directly applicable to a browser-side mel pipeline for
ASA — and the quantized-TGA storage trick is worth a look for cached
spectrogram artifacts.

### [casantosmu/audiodeck](https://github.com/casantosmu/audiodeck) — **3**
Self-hostable web spectrogram analyzer (Go server, browser-side render)
aimed at sniffing out fake-lossless files via frequency-cutoff
artifacts. 109★, TS, created Sep 2025. Analysis itself is shallow, but
the "thin Go shim + client-side spectrogram" topology is a clean shape
to mimic if ASA grows a library-scan UI.

### [undef13/splifft](https://github.com/undef13/splifft) — **3**
PyTorch separation + transcription toolkit: BS-Roformer / Mel-Roformer
/ MDX23C v3 separators, "beat this!" beat tracking, PESTO mono pitch,
basic-pitch poly pitch, behind a config-driven registry with 110+
community models. 40★, created Jun 2025. Ground-up rewrite of zfturbo's
MSST with a saner config surface — useful as a one-stop reference for
the current separation/transcription model zoo.

### [Ryan5453/demucs-next](https://github.com/Ryan5453/demucs-next) — **3**
Modernized Demucs fork: current PyTorch/TorchCodec, `uv` install, Cog
REST wrapper, and — most interestingly — ONNX export with WebGPU for
browser inference. 26★, alpha. The WebGPU path is the part to watch
if ASA ever wants in-browser separation; the rest is housekeeping.

### [mhartzel/freelcs](https://github.com/mhartzel/freelcs) — **3**
Hotfolder-driven EBU R128 loudness-correction server (Python, Docker,
mono → 5.1, per-stream). 25★, repo started 2012 but still pushed in
2026. Old code, but the drop-in/processed-out pipeline shape and the
visual loudness-history output are a useful reference for ASA's
loudness stage UX.

## Harmonia-relevant

### [dogayuksel/webKeyFinder](https://github.com/dogayuksel/webKeyFinder) — **4**
libKeyFinder (C++) compiled to WASM via Emscripten, fed by an
AudioWorkletProcessor and Web Workers, wrapped in Preact. 35★, TS,
pushed Mar 2026. This is the cleanest current template for the
exact plumbing Harmonia would need to add audio→key: WASM DSP in a
worker, worklet pulling PCM, all in-browser.

### [sildater/parangonar](https://github.com/sildater/parangonar) — **3**
Symbolic-music note alignment: dual-DTW, hierarchical DTW, a
transformer matcher ("TheGlueNote"), plus online/tempo-aware matchers
for live score-following, on top of Partitura I/O. 55★, Python, pushed
last week. Not on-stack, but if Harmonia ever lines reharmonizations
up to a performance (vs. an idealized score) this is the alignment
toolbox to reach for.

### [brightlikethelight/music21-mcp-server](https://github.com/brightlikethelight/music21-mcp-server) — **3**
FastMCP server exposing 13 music21 tools — Roman numerals, cadence
detection, voice leading, harmonization, counterpoint — plus HTTP/CLI
mirrors for when MCP itself misbehaves. 22★, Python. Worth a look as
the "music theory through an LLM" surface, but read the author's own
"40-50% MCP production success rate" caveat before treating it as
load-bearing.

## Both

### [bschoepke/ableton-live-mcp](https://github.com/bschoepke/ableton-live-mcp) — **3**
General-purpose Ableton MCP whose unlock is `eval` of arbitrary Python
inside Ableton's Object Model — plus pre-optimized tools for harmonic
analysis, signal-chain inspection, spectrogram generation, and
mastering setup. 184★, Python, created May 2026. More flexible than
producer-pal; the "harmonic analysis through the MCP" framing is the
one to mine for Harmonia-as-companion ideas.

### [uisato/ableton-mcp-extended](https://github.com/uisato/ableton-mcp-extended) — **3**
Extended Ableton MCP with parallel TCP + UDP servers (UDP for
low-latency real-time control), ElevenLabs TTS for in-session
narration/voice samples, and a custom-controller framework. 203★,
Python. Same family as producer-pal / ableton-mcp; the UDP path and
the controller-extension scaffold are the differentiators.

## Tangential but interesting

### [gluon/Void-LinkAudio](https://github.com/gluon/Void-LinkAudio) — **3**
Sample-accurate audio-over-LAN extending Ableton Link to Max, Pd,
TouchDesigner, VCV Rack, and Live 12.4+, with prebuilt binaries for
mac/Win/Linux. 41★, created Apr 2026. This is the parent project of
the already-logged `gluon/ofxAbletonLinkAudio` — listed here because
it covers the actually-popular hosts where the openFrameworks addon
was a single-platform shim.

### [phones24/ep133-export-to-daw](https://github.com/phones24/ep133-export-to-daw) — **3**
PWA that parses Teenage Engineering EP-133/1320/40 backup archives and
exports to Ableton 11+, DAWproject, REAPER, or plain MIDI — entirely
in-browser via WebMIDI, no device required. 88★, TS. Device-specific,
but the reverse-engineered file-format work and the DAWproject export
path are the reusable bits.
