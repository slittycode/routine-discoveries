## ASA-relevant

### [CPJKU/beat_this](https://github.com/CPJKU/beat_this) — **4**
Official ISMIR-2024 beat/downbeat tracker ("Beat This!") that drops the
traditional DBN post-processing step in favour of a transformer with a
shift-tolerant loss, shipping CLI + Python API and `.beats` export. 286★,
Python, created 2024 but pushed this week — a current, accurate drop-in
for ASA's tempo/beat stage that's lighter to wire up than madmom.

### [Polochon-street/bliss-rs](https://github.com/Polochon-street/bliss-rs) — **3**
Rust song-analysis library that extracts chroma, tempo, and timbral
features to compute track-to-track distance for automatic playlists
(Spotify-Radio style). 159★, pushed within the window; off-stack (wraps
aubio + librosa's chroma method) but the compact feature vector and
similarity framing are a clean reference if ASA grows a "tracks like
this" axis.

### [undef13/splifft](https://github.com/undef13/splifft) — **3**
Ground-up Python source-separation + transcription toolkit with a
registry of 110+ community models (BS-/Mel-RoFormer, MDX23C) plus beat
and pitch estimators, downloaded on demand. 40★, created Jun 2025. The
"plain data, pure functions, minimal deps" design and the model registry
are the useful bits if ASA ever adds a separation pre-stage — no novel
model of its own.

### [MTG/gaia](https://github.com/MTG/gaia) — **3**
Essentia's own C++/Python companion: similarity measures and SVM
classifiers over Essentia descriptors, producing the high-level models
Essentia loads to label music. 297★, still pushed in 2026. Since ASA
already rides Essentia.js, this is the upstream answer for "turn my
low-level descriptors into mood/genre/danceability tags" — but it's
C++/AGPL and not browser-friendly.

### [wavey-ai/mel-spec](https://github.com/wavey-ai/mel-spec) — **3**
Rust STFT + Whisper-compatible log-mel + Kaldi filterbanks + a small VAD,
benchmarked at ~476× realtime on M1 and compiled for the browser. 89★,
created 2023. ASR-oriented rather than MIR, but it's a fast, embeddable
reference for mel-spectrogram generation if ASA ever wants WASM mel
extraction independent of Essentia.

## Harmonia-relevant

### [pianosnake/ireal-reader](https://github.com/pianosnake/ireal-reader) — **4**
Node module that parses iReal Pro exports into JS objects: title/
composer/key/BPM plus a `measures` array of chord-symbol arrays
(`['C^7']`, `['Asus','A7susadd3']`), with repeats/segnos/codas expanded
to linear measures. 43★, JS, pushed this month. This is a direct ingest
path for Harmonia — the entire iReal Pro jazz corpus becomes structured
chord progressions with almost no parsing work.

### [CPJKU/partitura](https://github.com/CPJKU/partitura) — **3**
Python library for symbolic scores across MusicXML, MIDI, Humdrum **kern**,
and MEI, exposing notes (pitch/duration/voice/staff), parts, time
signatures, and beat maps. 350★, pushed this week. Off-stack (Python, not
JS) but the cleanest reference for a complete symbolic data model if
Harmonia ever needs richer score import/export than Tonal.js + MusicXML.

## Both

### [a1ex90/MusicalKeyCNN](https://github.com/a1ex90/MusicalKeyCNN) — **4**
CQT-spectrogram CNN (after Korzeniowski & Widmer) for key estimation with
pitch-shift augmentation, trained on GiantSteps, outputting Camelot-wheel
labels at ~73.5% MIREX-weighted — competitive with Mixed In Key. 50★,
Python, created Jun 2025. Full preprocessing/training/eval code, not a
wrapper: a key signal both for ASA's tonal analysis and for grounding
Harmonia's reharmonization in a detected key.

### [ifeelvoid/keyfinder](https://github.com/ifeelvoid/keyfinder) — **3**
Native macOS app + VST/AU that detects key (Camelot), BPM, and renders
waveforms via a custom Krumhansl-Schmuckler engine (16k-point FFT, bass
weighting), sharing one Swift `KeyFinderEngine` package across app and
plugin. 45★, created Mar 2026. Off-stack (Swift/macOS) but a tidy
worked example of a from-scratch K-S key detector and the app↔plugin
shared-engine split.

## Tangential but interesting

### [marcus/good-composer](https://github.com/marcus/good-composer) — **3**
Streams MIDI from an LLM (Ollama / OpenRouter) over WebSocket and plays
it live with a Tone.js piano-roll while it generates. 33★, JS, created
Dec 2025. Not analysis or theory, but the streaming-generation +
synchronized piano-roll visualization is the closest reference if
Harmonia ever wants an LLM-driven "reharm as you watch" channel.
