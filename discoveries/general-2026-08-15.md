## Finds

### 1. [frankea/Whisky](https://github.com/frankea/Whisky) — Mac gaming (CrossOver)
Actively maintained community continuation of Whisky, a native macOS Wine wrapper
for running Windows games/apps on Apple Silicon.

**Evidence:** 401★, 28 forks, 11 open issues under active triage, pushed
2026-08-13 (2 days before this sweep). Exists specifically because the original
`whisky-app/whisky` was archived (April 2025) and the maintainer picked up the
backlog. Ships DXMT (a Metal-native DX12 backend) and Game Porting Toolkit
integration — genuinely newer engineering than what CrossOver ships.

**Why it's worth attention:** Sits right next to CrossOver in the same problem
space — a free, Apple-Silicon-native alternative worth A/B-ing against whatever
CrossOver is currently doing for specific titles, especially anything CrossOver
runs poorly.

**First move:** Install it alongside CrossOver, pick one game that currently runs
suboptimally under CrossOver, and compare DXMT vs. CrossOver's D3DMetal backend on
FPS/stability for that title.

### 2. [guyfedwards/nom](https://github.com/guyfedwards/nom) — terminal news reader
A terminal RSS/Atom reader (Go, Bubbletea TUI) with local sync and
Miniflux/FreshRSS backend support, markdown-rendered reading via Glow.

**Evidence:** 739★, 52 forks, 23 contributors, latest release v3.3.0
(2026-03-19), pushed 2026-07-08, 33 open issues under active work. Multi-year,
multi-contributor project, not a solo weekend build.

**Why it's worth attention:** This is the exact project already half-built (a
terminal news reader) — a working, maintained implementation of the same idea, so
it's a direct comparison point rather than a tangent.

**First move:** Run it for a week against real feeds, and note which design
choices (backend abstraction, keybindings, read-later state) are worth stealing
outright vs. deliberately doing differently before picking the own build back up.

### 3. [tonaljs/tonal](https://github.com/tonaljs/tonal) — music theory library (TS)
A mature, batteries-included music theory library for JS/TS: notes, intervals,
scales, chords, keys, progressions, roman numerals.

**Evidence:** 4,216★, 251 forks, 40 open issues, pushed 2026-07-28. Ten years old,
still releasing, and the de facto standard theory layer underneath a wide range of
chord/key tools in the wild.

**Why it's worth attention:** This is the foundation layer for the half-built
chord progression tool. Hand-rolling chord/scale/key math is a classic reason that
kind of project stalls — this replaces it with a tested, typed library.

**First move:** Swap any hand-rolled chord/scale logic in the chord tool for
tonal's `Chord`/`Progression`/`RomanNumeral` modules and see how much custom code
just disappears.

### 4. [karakeep-app/karakeep](https://github.com/karakeep-app/karakeep) — notes/reading
Self-hostable "bookmark everything" app (links, notes, images) with AI-based
automatic tagging and full-text search — built so saved things resurface instead
of vanishing into a pile.

**Evidence:** 28,356★, 1,434 forks, 678 open issues under active work, pushed
2026-08-13. Docker images, mobile apps, one of the more actively developed
self-hosted projects right now — well past any hype-spike phase.

**Why it's worth attention:** Directly answers "reads a lot, keeps more notes than
gets used" — the AI tagging/search is specifically built to do the organizing work
that manual note-keeping tends to skip.

**First move:** Self-host it (single `docker-compose.yml`) and dump a week's worth
of saved articles/notes into it to see whether the tagging and search actually
surface things again later, not just at save time.

### 5. [ghostfolio/ghostfolio](https://github.com/ghostfolio/ghostfolio) — portfolio tracker
Open-source, self-hosted wealth-management dashboard (Angular + NestJS + Prisma)
that aggregates holdings across brokers/exchanges into one view.

**Evidence:** 9,127★, 1,271 forks, pushed 2026-08-14 (day of this sweep), active
discussions and hundreds of open issues under triage, official Docker images,
running continuously since 2021 — long past any spike.

**Why it's worth attention:** Matches "hold some shares not understood as well as
they should be" almost exactly — it exists to turn scattered holdings into
allocation/performance/fee breakdowns without handing the data to another SaaS.

**First move:** Try the hosted demo/sandbox mode first, then import one account's
real holdings via CSV and see if the allocation/performance views actually clarify
anything that isn't already obvious from the broker's own app.

### 6. [charmbracelet/crush](https://github.com/charmbracelet/crush) — terminal coding agent
Charm's own terminal AI coding agent (Go, Bubbletea-based) — a direct sibling to
the opencode fork already in progress, built by the team behind the TUI libraries
(Bubbletea/Lipgloss/Glamour) that also power `nom` above.

**Evidence:** 27,382★, 2,158 forks, 630 open issues under active work, pushed
2026-08-14 — built by a well-resourced, long-running OSS shop (Charm), not a
one-off.

**Why it's worth attention:** Not a fork target (different stack — Go/Bubbletea vs.
the opencode fork's TS/Bun), but the closest actively-developed sibling project to
study for UX and agent-loop decisions. Its underlying TUI libraries are also
exactly what would polish the terminal news reader (nom already uses them).

**First move:** Run crush on one real task for a day, note anywhere its TUI/agent-
loop choices diverge from the opencode fork's, and flag anything worth
backporting.
