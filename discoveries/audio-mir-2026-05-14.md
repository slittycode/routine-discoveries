## ASA-relevant

### [openclaw/songsee](https://github.com/openclaw/songsee) — **4**
Go CLI that renders 9 frequency-domain views — spectrogram, mel,
chroma, HPSS, self-similarity, loudness, tempogram, MFCC, spectral
flux — from any ffmpeg-readable file with no Python deps. 59★, created
Jan 2026. ASA needs almost exactly this set of mel/loudness/tonal
visuals; the native-Go FFT pipeline and the grid-combining output are
worth studying even though ASA runs in-browser.

### [DarienBrito/EssentiaTD](https://github.com/DarienBrito/EssentiaTD) — **4**
Five C++ CHOP plugins wrapping Essentia for TouchDesigner: spectrum,
mel bands, MFCCs, pitch, key/scale, onset/BPM, and EBU R128 loudness,
in both realtime and batch modes. 91★, created Mar 2026. It's the
cleanest recent map of which Essentia algorithms cover ASA's
tonal-balance / dynamics / loudness brief and how to split realtime
vs full-file analysis.

### [jhartquist/resonators](https://github.com/jhartquist/resonators) — **4**
Rust implementation of the Resonate algorithm — a fixed-memory,
per-sample alternative to FFT/CQT for low-latency spectral analysis —
with Python and WebAssembly bindings. 86★, created Apr 2026. The WASM
target makes it a plausible drop-in for a browser DSP stage where ASA
wants sharper, per-bin time-frequency tradeoffs than a stock STFT.

### [Angel2mp3/AudioAuditor](https://github.com/Angel2mp3/AudioAuditor) — **4**
Windows app that flags fake-lossless upsampling, digital clipping,
MQA, and AI-generated audio, plus dynamic-range and true-peak (4×
oversampled) measurement and a log-frequency spectrogram viewer. 70★,
created Mar 2026. The dynamics + true-peak + spectral-ceiling logic
overlaps ASA's dynamics stage directly; it's C#/Windows so treat it as
reference, not reuse.

### [WB2024/Essentia-to-Metadata](https://github.com/WB2024/Essentia-to-Metadata) — **3**
Local genre/mood tagger built on Essentia's Discogs-Effnet embeddings,
Discogs-400 genre CNN, and MTG-Jamendo mood classifier, writing tags
straight to files. 75★, created Feb 2026. Relevant to ASA only as a
worked example of running Essentia's pretrained ML models fully
offline — it's classification, not the tonal/loudness analysis ASA
centers on.

### [craiglush/navidrome-mood-plugin](https://github.com/craiglush/navidrome-mood-plugin) — **3**
Navidrome plugin using essentia-tensorflow + Discogs-EffNet to score
mood, danceability, energy, and BPM with genre-aware corrections, then
auto-builds 13 themed playlists. 55★, created Mar 2026. Useful as a
reference for Essentia-TF embeddings and the genre-context-boost
trick; it's a media-server plugin, not a DSP library.

### [NeptuneHub/AudioMuse-AI-NV-plugin](https://github.com/NeptuneHub/AudioMuse-AI-NV-plugin) — **3**
Navidrome plugin doing sonic-analysis-based song/artist similarity for
instant-mix and radio features, backed by a Flask + Worker analysis
container. 240★, created Jan 2026. Thinner on disclosed DSP detail
than the mood plugin above — included as a second data point on
Essentia-driven similarity architecture; drop if similarity isn't a
use case you're chasing.

## Both

### [JuzzyDee/audio-analyzer-rs](https://github.com/JuzzyDee/audio-analyzer-rs) — **5**
Pure-Rust MCP server that extracts the whole MIR stack — spectral
centroid/bandwidth/rolloff/flatness, Krumhansl-Schmuckler key
detection, pitch-class distribution, tonnetz, MFCCs, EBU R128
LUFS/true-peak/LRA, crest factor, HPSS, stereo field, and section
boundaries — in under 2s per track with no Python or FFmpeg. 21★,
created Mar 2026. It's essentially ASA's entire feature set in one
dependency-free crate, and the key / pitch-class / tonnetz outputs
feed Harmonia's harmonic analysis too.

## Harmonia-relevant

### [marcus/good-composer](https://github.com/marcus/good-composer) — **3**
Streams MIDI from an LLM (Ollama or OpenRouter) over WebSocket with a
custom piano-roll that draws notes as they generate; FastAPI backend,
Tone.js frontend. 33★, created Dec 2025. No music-theory library
involved — relevant to Harmonia only as a pattern for real-time MIDI
playback and progressive piano-roll rendering, not for reharm logic.

## Tangential but interesting

### [Ryan5453/demucs-next](https://github.com/Ryan5453/demucs-next) — **3**
Modernized fork of Demucs (current PyTorch/TorchCodec, Cog REST
integration) reporting ~2–3× faster separation at equal-or-better SDR.
26★, alpha. Only relevant if ASA adds a stem-separation pre-stage;
it's a straight speed/packaging refresh of a model you'd already reach
for.
