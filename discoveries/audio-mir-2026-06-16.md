## ASA-relevant

### [spotify/basic-pitch](https://github.com/spotify/basic-pitch) — **5**
Spotify's polyphonic audio-to-MIDI converter with pitch-bend detection:
lightweight TF/CoreML model producing note events with onset, offset, pitch
confidence, and pitch bend from any audio file. Stars: 5179, actively
maintained. ASA currently produces chords, beats, and structure but no MIDI
— basic-pitch fills that gap directly, and MIDI is the native currency of
Ableton's clip/piano-roll workflow. It's the most direct bridge between
Phase 1 measurements and actionable Ableton reconstruction advice.

### [mir-aidj/all-in-one](https://github.com/mir-aidj/all-in-one) — **5**
Single-inference music structure analyzer that jointly estimates beats,
downbeats, section boundaries (verse/chorus/bridge labels), chords, and key
— all from one PyTorch model pass. Stars: 784. ASA currently runs msaf,
Essentia, and beat_this separately for these tasks; all-in-one would replace
or validate all of them with a unified, ISMIR-published model (ISMIR 2023).
The multi-task framing also means cross-task consistency that sequential
pipelines can't guarantee.

### [Music-and-Culture-Technology-Lab/omnizart](https://github.com/Music-and-Culture-Technology-Lab/omnizart) — **4**
Python library for omniscient music transcription: piano, guitar, bass,
drums, chords, beats, vocal melody — each a separate neural model, all
callable via a shared CLI or Python API. Stars: 1912. Where basic-pitch gives
polyphonic MIDI and all-in-one gives structure, omnizart adds instrument-
specific transcription (drum hits, guitar tabs, bass lines) that ASA's
current Demucs-based stem separation doesn't attempt. Plugin for completing
the transcription→recommendation pipeline.

### [CPJKU/madmom](https://github.com/CPJKU/madmom) — **4**
Python audio signal processing library from the JKU research group: RNN/CNN
beat/downbeat tracking, onset detection, key estimation, and chord
recognition — many with pre-trained neural models. Stars: 1660. CPJKU also
makes beat_this (already in ASA's stack); madmom is the older, broader
library and its chord HMM and onset models complement what Essentia provides.
Direct peer/alternative for ASA's temporal analysis.

### [KinWaiCheuk/nnAudio](https://github.com/KinWaiCheuk/nnAudio) — **4**
PyTorch 1D convolution network layers that compute mel spectrograms, CQT,
STFT, and other time-frequency representations entirely on GPU — as `nn.Module`
layers that live in the computation graph. Stars: 1126. ASA is already
PyTorch; replacing librosa's CPU-bound spectrogram math with nnAudio means
spectrogram computation benefits from GPU batching and can be differentiated
through. Especially relevant to the canvas-based mel spectrogram and any
future model that takes raw mel input.

### [hidingwill/AbletonBridge](https://github.com/hidingwill/AbletonBridge) — **4**
353 tools connecting LLMs to Ableton Live 12 via MCP, OSC, M4L, TCP/UDP —
covering session view, clip manipulation, device parameters, mixer, and
transport. Stars: 39, active (2026). ASA's Phase 2 Gemini layer produces
Ableton device/parameter recommendations; AbletonBridge is the execution
layer that turns those recommendations into actual Live state changes. Most
direct reference for how ASA's output maps to real LOM operations.

### [mjhydri/BeatNet](https://github.com/mjhydri/BeatNet) — **4**
Real-time joint beat, downbeat, tempo, and meter (time-signature) detection
via CRNN + particle filtering, with both online and offline modes. Stars: 494,
ISMIR 2021. ASA has beat_this for beats but meter/time-signature detection
is absent — BeatNet fills that slot directly. Time-signature is the piece
of rhythmic context ASA recommendations can't currently cite.

### [kwatcharasupat/query-bandit](https://github.com/kwatcharasupat/query-bandit) — **4**
Query-conditioned stem separation that goes beyond the fixed 4-stem (vocals/
drums/bass/other) schema: you pass a text or audio query and the model
extracts that custom stem. Stars: 100, ISMIR 2024. ASA uses Demucs's fixed
schema; Banquet's query-based approach would let ASA isolate e.g. "lead
synth" or "room reverb tail" — information that maps directly to per-element
Ableton reconstruction advice.

## Tangential but interesting

### [FunAudioLLM/SenseVoice](https://github.com/FunAudioLLM/SenseVoice) — **3**
Speech+audio understanding model: ASR + emotion recognition + audio event
detection across 50+ languages, 15× faster than Whisper. Stars: 8588. Not
music-specific (it flags speech emotion and sound events, not musical key or
chords), but its audio-event-detection head (dog bark, siren, applause, etc.)
is directly relevant to ASA's LLM interpretation layer if the project ever
wants to classify non-musical content within a track or identify intro/outro
texture events.

### [lars76/swift-f0](https://github.com/lars76/swift-f0) — **3**
Fast, accurate F0 (fundamental frequency) detector using a lightweight CNN,
with ONNX export for inference without PyTorch. Stars: 166, created 2025.
ASA uses torchcrepe for melody/F0; swift-f0 is a lighter alternative with
competitive accuracy and a smaller runtime footprint, useful if torchcrepe
becomes a bottleneck or if ASA needs to run F0 in a lighter deployment.

### [olilarkin/librosa.cpp](https://github.com/olilarkin/librosa.cpp) — **3**
C++17 port of librosa (mel spectrogram, beat tracking, pitch detection)
with Swift Package Manager support and a WASM build. Stars: 47, created
April 2026. Marginal now — ASA uses Python librosa natively — but it's
the closest reference if ASA ever needs a native-performance sidecar for
spectral features (e.g. an Ableton Extension or Max for Live device that
mirrors ASA's analysis).

### [cjbayron/autochord](https://github.com/cjbayron/autochord) — **3**
Automatic chord recognition ISMIR 2021 Late-Breaking Demo: CRNN producing
timestamped Harte-notation chord labels from audio. Stars: 161. Complements
ASA's existing chord detection; consonance-ACE (already logged, rated 4) is
the stronger modern model, but autochord is a simpler drop-in for testing
chord pipelines.

### [madisonrickert/ablevsep](https://github.com/madisonrickert/ablevsep) — **3**
Ableton Live Extension that calls MVSEP's 100+ source-separation models on
any AudioClip, returning separated stems as clips inside Live. Stars: 29,
created June 2026. Shows what the end-state of ASA's stem-separation→Ableton
workflow looks like from the user's side — a useful reference for how to
package ASA's analysis results as actionable Live commands.

### [cycfi/q](https://github.com/cycfi/q) — **3**
C++20 DSP library with pitch tracking (MIDI-linked oscillators), effects,
and a signal-processing DSL based on function composition. Stars: 1394.
Off-stack for ASA's Python backend but a strong C++ DSP reference if ASA
ever gains a native sidecar (e.g. an Ableton Extension that runs local
inference). Pitch tracking and onset algorithms are readable reference
implementations.
